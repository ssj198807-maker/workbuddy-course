# 第二篇 · 案例篇 · 课纲

> **本篇目标**：用 11 个真实业务场景，讲"AI 团队怎么组队、怎么干活、怎么交付"。
> **课时总计**：13 小时（11 节 × 平均 70 min）
> **难度**：★★ 到 ★★★★★
> **核心交付物**：1 支"为你的业务定制"的 AI 团队
> **本篇是整个教学体系的核心**——第一篇打底，第三篇深化，第四篇落地，但所有的"AI 团队"设计模式都在本篇讲透。

## 第 11 章 · 办公三件套：Word、Excel、PPT

| 项 | 内容 |
|---|---|
| **课时** | 90 min |
| **难度** | ★★ |
| **核心目标** | 用 AI 团队替代 70% 日常办公任务 |
| **学习成果** | 3 份成品文件 + 1 套可复用模板 |

### 章节内容

#### 11.1 团队设计（15 min）
- **Word 专家团** = 文档整理 Agent + 模板格式化 Agent + 校对 Agent
- **Excel 专家团** = 数据清洗 Agent + 公式生成 Agent + 图表生成 Agent
- **PPT 专家团** = 大纲生成 Agent + 内容扩展 Agent + 视觉设计 Agent

#### 11.2 Word 任务实战（20 min）
- 任务示例：「把 5 份客户合同扫描件整理成统一格式的 Word 文档」
- 关键技巧：
  - **绝对不要让 AI 改合同条款**——只做格式整理
  - 验收标准：双栏对齐、字号统一、签字位保留

#### 11.3 Excel 任务实战（25 min）
- 任务示例：「清洗 119 份门店销售数据，生成可交互运营看板」
- 关键技巧（**蓝皮书核心场景**）：
  - **数据清洗要先有"清洗规则"**，不要让 AI 自己决定
  - **不擅自补全无法确认的数据**——标"待确认"而不是猜
  - **公式必须解释用途**——学员要看得懂
- 延伸参考：三哥 wiki 内《门店 Excel 看板》案例

#### 11.4 PPT 任务实战（25 min）
- 任务示例：「基于本月工作日志，生成一份 12 页的月度汇报 PPT」
- 关键技巧：
  - **每页只保留一个核心观点**——不为凑页数拆段
  - **图表由 AI 生成，但配文由你写**——避免"AI 腔"
  - **设计风格必须有参考图**——别让 AI 自由发挥

#### 11.5 三件套的协作（5 min）
- 「客户分析报告」= Excel 数据 + Word 解读 + PPT 展示
- 一个团队调度，三个产品

### 教学要点
- ✅ **每个文件都要有"参考样板"**——AI 没有参考就一定做错
- ❌ 不要演示"完全让 AI 自由发挥"

### 课后作业
- 用 AI 团队完成 1 份 Word + 1 份 Excel + 1 份 PPT
- 三份必须服务于同一个真实业务场景

## 第 12 章 · 整理桌面文件这些小事

| 项 | 内容 |
|---|---|
| **课时** | 45 min |
| **难度** | ★★ |
| **核心目标** | 建立"文件管理 SOP" |
| **学习成果** | 1 份个人文件管理规范 + 1 个自动化整理任务 |

### 章节内容

#### 12.1 为什么先讲"小事"（5 min）
- 案例：「我下载过 2000+ 份资料，500+ 份是重复的」
- 文件管理是"AI 团队第一战"——易上手、见效快、不涉及外发
- 蓝皮书反复强调：**先练小事，再上大事**

#### 12.2 三步整理法（20 min）
```
1. 分类规则    → 2. 备份检查    → 3. 执行整理
```
- 分类规则举例（按业务场景）：
  - 工作中：客户名 / 项目名 / 月份
  - 学习中：领域 / 媒介 / 状态（未读/在读/已读）
  - 个人：财务 / 健康 / 旅行
- 备份检查三件套：
  - 重要文件是否有副本？
  - 是否同步到云盘？
  - 整理后能否恢复？

#### 12.3 AI 团队设计（10 min）
- **分类 Agent**：用 LLM 理解文件内容（不是只看扩展名）
- **备份 Agent**：自动同步到云盘
- **归档 Agent**：按规则移动 + 改名

#### 12.4 现场演示（10 min）
- 跑通一个 500 文件的桌面整理
- 演示失败模式：扩展名对了但内容不对（如 .md 里其实是 YAML）

### 教学要点
- ✅ **"整理前先备份"**——必须强调
- ❌ 不要演示"自动删除"——蓝皮书铁律

### 课后作业
- 整理自己的桌面 + Downloads 文件夹
- 写出自己的"分类规则"文档（一份 SOP）

## 第 13 章 · 远程控制你的电脑

| 项 | 内容 |
|---|---|
| **课时** | 30 min |
| **难度** | ★★ |
| **核心目标** | 不在电脑前也能跑 AI 任务 |
| **学习成果** | 配通 1 个远程任务 |

### 章节内容

#### 13.1 远程的三种实现（10 min）
- **IM 触发**：飞书/钉钉群里 @机器人触发任务
- **定时任务**：早上 9 点自动跑
- **Webhook 触发**：外部系统（CRM/工单）触发

#### 13.2 场景实战（15 min）
- 场景 A：客户在群里问问题 → 机器人自动查 CRM 回答
- 场景 B：销售日报自动汇总 → 早上 9 点推到飞书群
- 场景 C：竞品网站监控 → 变动推 IM

#### 13.3 安全边界（5 min）
- 哪些操作可以远程做（查询、汇总、推送）
- 哪些不可以远程做（删文件、转账、发合同）
- **必须有的"二次确认"机制**

### 教学要点
- ✅ 强调**远程 ≠ 无边界**
- ❌ 不要演示"自动转账"等高危场景

### 课后作业
- 配 1 个远程触发的查询/汇总任务
- 给任务加"二次确认"机制

## 第 14 章 · 生活助手的价值

| 项 | 内容 |
|---|---|
| **课时** | 30 min |
| **难度** | ★ |
| **核心目标** | 让 AI 帮你处理琐碎 |
| **学习成果** | 5 个生活场景小工具 |

### 章节内容

#### 14.1 为什么把生活场景放在第二篇（5 min）
- 生活场景难度低，**特别适合做"练手项目"**
- 把工作中已经会的套路迁移到生活

#### 14.2 5 个经典场景（20 min）

| 场景 | AI 团队 | 边界 |
|---|---|---|
| **每日天气 + 穿衣建议** | 天气 API + LLM 改写 | 不发朋友圈，只给自己 |
| **每周菜谱** | 冰箱照片 + 营养 API + 菜谱生成 | 过敏原必标 |
| **家庭账本** | 微信账单 + 分类 Agent | 不连银行 App |
| **纪念日提醒** | 日历 + LLM 写祝福语 | 不自动发红包 |
| **旅行规划** | 高德/小红书 API + 行程生成 | 不订机票/酒店 |

#### 14.3 生活 vs 工作的关键差异（5 min）
- 工作中：**任务驱动**
- 生活中：**场景驱动**（没有 deadline，AI 容易做"过设计"）
- 解决：每个生活场景**必须设"完成标志"**，没设就停不下来

### 教学要点
- ✅ 让学员**从生活场景起步，建立"完成感"**
- ❌ 不要演示"全自动管家"——那是科幻

### 课后作业
- 选 3 个生活场景，跑通至少 1 个
- 给每个场景写"完成标志"

## 第 15 章 · 资讯整合：把信息流变成每日通知

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 让 AI 替你"读"信息 |
| **学习成果** | 1 套"每日推送"工作流 |

### 章节内容

#### 15.1 信息流的三种处理（10 min）
- **被动接收**：每天刷 30 min 但记不住
- **手动整理**：用工具收藏但不再看
- **AI 推送**：每天 9 点把"我关心的 5 件事"送到眼前

#### 15.2 资讯整合 4 步法（20 min）
```
1. 源筛选   → 2. 内容抓取   → 3. AI 摘要   → 4. 推送通知
```

| 步 | 工具 | 失败模式 |
|---|---|---|
| 源筛选 | RSS / API / 爬虫 | 选了太多 → 噪音 |
| 内容抓取 | 网页抓取 Skill | 反爬 / 付费墙 |
| AI 摘要 | LLM | 摘要变"读后感" |
| 推送通知 | 飞书 / 邮件 / 公众号 | 推送时间不对 |

#### 15.3 团队设计（15 min）
- **采集 Agent**：5 个 RSS 源
- **过滤 Agent**：关键词 + 重复检测
- **摘要 Agent**：每条 200 字内 + 3 条关键判断
- **推送 Agent**：早 9 点准时推飞书

#### 15.4 现场演示（10 min）
- 配一个"AI 行业每日 5 条"推送
- 演示失败模式：源失效、摘要过长、推送时间错

#### 15.5 进阶：和知识库联动（5 min）
- 推送的每条资讯可以**自动归入"待读"知识库**
- 读完/打标签后自动归类（参考第 16 章）

### 教学要点
- ✅ 强调**"少而准"**——5 条好资讯 > 50 条噪音
- ❌ 不要演示"全网爬取"——容易被封号

### 课后作业
- 配 1 套每日资讯推送（最多 5 个源）
- 跑 7 天，统计"真正读完"的比例（应 > 60%）

## 第 16 章 · 收藏不是知识管理

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 解决"收藏夹吃灰" |
| **学习成果** | 1 个可持续运转的个人知识库 |

### 章节内容

#### 16.1 为什么收藏 ≠ 知识管理（10 min）
- 典型陷阱：
  - **收藏即遗忘**：存了 500 条从未看第二条
  - **分类强迫症**：花 2 小时分类 100 条
  - **完美主义**：找不到完美工具就一直不开始
- 蓝皮书判断标准：**"能再次用起来"才是知识管理**

#### 16.2 三层知识库结构（15 min）
```
未读层（INBOX）    →    主题层（TOPIC）    →    行动层（DOING）
   1 周内消化              3-6 个月回顾            当下能用的素材
```
- **INBOX**：所有进来的素材都先丢这里
- **TOPIC**：按主题归档（不是按来源）
- **DOING**：当下用得上的素材集合

#### 16.3 团队设计（15 min）
- **抓取 Agent**：公众号 / 微信 / 网页 → INBOX
- **主题归类 Agent**：LLM 判断主题 + 打标签
- **行动提取 Agent**：从素材中提取"可执行清单"
- **周报 Agent**：每周日汇总"本周新增 + 待消化"

#### 16.4 现场演示（10 min）
- 配一个"微信公众号 → 知识库"工作流
- 演示失败模式：抓取失败、归类错误、行动提取失真

#### 16.5 与三哥知识库体系的连接（5 min）
- 蓝皮书的 16 章 = 三哥 wiki 的**生产链路**
- 三哥 wiki 内已用 INBOX 整理 + projects/ 归档
- 学员可以**直接复用三哥的分类规范**

### 教学要点
- ✅ **强调"先乱后治"**——别追求完美分类
- ✅ 引用三哥 wiki 实操案例，可信度更高
- ❌ 不要演示"全自动知识库"——一定会有失败

### 课后作业
- 配 1 个 INBOX → 知识库工作流
- 跑 30 天，统计"30 天后还能用"的素材比例

## 第 17 章 · 会议结束不是终点

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 让会议真正产出行动 |
| **学习成果** | 1 套"会议 → 行动"闭环 |

### 章节内容

#### 17.1 会议的真相（10 min）
- 数据：
  - **70% 的会议没有明确纪要**
  - **50% 的待办在会后 1 周被遗忘**
  - **30% 的会议可以邮件替代**
- AI 团队的真正价值：让会议的"待办"活下去

#### 17.2 会议全流程 AI 化（20 min）
```
会前  →  会中  →  会后
排议程   实时纪要   待办分发 + 进度跟踪
```

| 阶段 | AI 任务 | 关键技巧 |
|---|---|---|
| 会前 | 拉历史邮件/文档，生成议程 | 必须人工确认议程 |
| 会中 | 实时转录 + 关键决策标注 | 关键决策必须复读一次 |
| 会后 | 整理纪要 + 拆解待办 + 分配 | 待办必须有时间 + 负责人 |

#### 17.3 团队设计（15 min）
- **会前 Agent**：拉资料 + 生成议程
- **会中 Agent**：实时转录（**不上传云端**）
- **会后 Agent**：纪要 + 待办 + 飞书任务
- **跟踪 Agent**：每周检查待办进度

#### 17.4 现场演示（10 min）
- 跑通 1 个 30 分钟会议的全流程
- 演示"待办没被完成"的兜底机制

#### 17.5 安全红线（5 min）
- **会议录音必须本地化**——不能上传到第三方
- **纪要中的人名/金额必须二次确认**——AI 转录可能错
- **待办分配必须人工**——AI 不能直接 @ 别人

### 教学要点
- ✅ **会后 24 小时内必须分发明**——错过这个窗口，待办就死了
- ❌ 不要演示"自动 @ 别人"——边界感差

### 课后作业
- 跑 1 个真实会议的全流程
- 统计"1 周后还在跟"的待办比例（应 > 70%）

## 第 18 章 · 把投资分析变成你的日常

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 让 AI 团队替你"读财报" |
| **学习成果** | 1 套"个人投资看板" |

### 章节内容

#### 18.1 个人投资分析的现实（10 min）
- 三个常见误区：
  - 每天看行情 → 频繁交易 → 亏损
  - 听消息面 → 追涨杀跌 → 后悔
  - 不会读财报 → 错过好公司 / 踩雷差公司
- AI 团队的定位：**替你做"读 + 整理"，决策你做**

#### 18.2 投资分析的 4 步法（15 min）
```
1. 选标的    → 2. 读财报    → 3. 横向对比    → 4. 决策记录
```

| 步 | AI 任务 | 边界 |
|---|---|---|
| 选标的 | 监控公告 + 行业新闻 | 不推荐买卖 |
| 读财报 | 抓年报 + 关键指标提取 | 不预测股价 |
| 横向对比 | 同行业 5 家公司对比表 | 不写"应该买" |
| 决策记录 | 买入卖出 + 理由 | 不自动下单 |

#### 18.3 团队设计（15 min）
- **监控 Agent**：公告 + 研报 + 新闻
- **财报 Agent**：年报抓取 + 关键指标提取（参考三哥 wiki《上市公司深度研究方法》案例）
- **对比 Agent**：同行业 5 家公司横向对比
- **复盘 Agent**：每季度决策复盘

#### 18.4 现场演示（10 min）
- 跑通"读一份年报 → 提取 5 个关键指标 → 写一句话总结"
- 演示失败模式：年报里数据错误、AI 提取字段错位

#### 18.5 强红线（5 min）
- **绝对不能自动下单**——所有买卖必须人工
- **绝对不能给"建议买/卖"判断**——只给事实
- **所有数据来源必须可追溯**——AI 不能编年报数字

### 教学要点
- ✅ 强调**"AI 给事实，决策你做"**
- ❌ 不要演示"AI 选股"——蓝皮书反模式

### 课后作业
- 用 AI 团队分析 1 家公司（不一定是自己持仓的）
- 写出"事实清单"+"我自己的判断"（分清楚）

## 第 19 章 · 一句话召唤 AI 视频团队 ★★★ 本篇重点

> **本章是第二篇的核心案例，是"AI 团队组队思维"的最完整示范。**
> **完整教学文档见**：[`/teaching/19-video-team`](/teaching/19-video-team)

| 项 | 内容 |
|---|---|
| **课时** | 120 min（拆为 2 节，每节 60 min） |
| **难度** | ★★★★ |
| **核心目标** | 理解"两支 AI 团队协作"的最完整范式 |
| **学习成果** | 1 支视频生产团队 + 1 支爆款拆解团队 |

### 章节内容

#### 19.1 视频工作的真相（10 min）
- 真人做视频要多久？
  - 选题：1-2 小时
  - 写脚本：2-3 小时
  - 拍摄/剪辑：4-8 小时
  - 调封面、写标题：1 小时
  - 发布 + 回复评论：1 小时
  - **总计：9-15 小时/条**
- AI 团队能做什么？
  - 选题、脚本、视觉、剪辑、发布——**全流程可自动化**
  - **但前提是：你得"会组队"**

#### 19.2 两支团队的整体设计（15 min）
```
                ┌──────────────────────────────┐
                │   视频生产团队（生成）         │
                │                              │
爆款拆解团队 ───┤   选题 → 脚本 → 视觉 → 剪辑  │
（学习）         │                              │
                │   ↓ 人工验收 + 发布           │
                └──────────────────────────────┘
                              ↓
                        数据复盘
                              ↓
                        回到拆解
```

**两支团队不是替代关系，是互补**：
- **生产团队**：解决"今天怎么做一条出来"
- **拆解团队**：解决"为什么别人那条能火，我能学到什么"

#### 19.3 视频生产团队（30 min）

**7 个 Agent 角色**：

| 角色 | 职责 | 工具/技术 |
|---|---|---|
| **阿刷**（团长） | 任务调度、流程编排、结果汇总 | WorkBuddy 调度 |
| **阿热点** | 监控热点、推荐选题 | 微博热搜 + 抖音热点 + 自定义信号源 |
| **阿脚本** | 写脚本、改脚本 | LLM + 爆款脚本库 |
| **阿分镜** | 把脚本拆成镜头 | LLM + 镜头模板 |
| **阿渲染** | 生成视觉素材 | 文生图/文生视频模型 |
| **阿剪辑** | 合成 + 字幕 + 配乐 | ffmpeg + 剪辑模板 |
| **阿发布** | 标题 + 标签 + 封面 + 多平台 | 云手机 + 平台 API |

**6 步生产流程**：
```
热点监控 → 脚本生成 → 分镜设计 → 视觉生成 → 剪辑合成 → 标题封面
```

**关键设计原则**：
1. **每个 Agent 任务说明必须明确"验收标准"**
2. **必须配"人工验收"节点**——蓝皮书铁律
3. **默认不要自动发布**——除非账号、内容、合规都已人工确认

#### 19.4 爆款视频拆解团队（25 min）

**为什么需要拆解团队**：
- 生产团队只会"做"，不会"学"
- 内容创作者真正需要的是"为什么别人能爆"
- 拆解是为了**学结构、学方法，不是搬运**

**3 个 Agent 角色**：

| 角色 | 职责 | 工具/技术 |
|---|---|---|
| **阿爆**（团长） | 拆解总控、流程编排 | WorkBuddy 调度 |
| **小凯** | 音频处理与转录 | ffmpeg + ASR |
| **小淼** | 视频理解与镜头裁切 | 视频理解 API + ffmpeg |

**3 步拆解流程**：
```
1. 视频下载（API → Playwright → yt-dlp 三层降级）
2. 音频提取 + 文案转写
3. 视频理解 + 镜头语言分析
```

**安全边界**：
- **遵守平台条款、版权授权、合理使用范围**
- 拆解是"学结构"，不是"搬运原视频"
- 仿拍建议必须基于**已公开的镜头规律**，不是原视频画面

#### 19.5 两支团队如何形成闭环（15 min）

```
爆款视频链接
    ↓
拆解团队：转写、镜头、节奏、仿拍建议
    ↓
形成拍摄手册和内容规律
    ↓
生成团队：热点、脚本、分镜、渲染
    ↓
人工验收 + 发布
    ↓
数据复盘
    ↓
回到拆解
```

**这是专家团比单个工具更有意义的地方**：
- 不只是做一条视频
- 让"学习、生产、发布、复盘"变成**可重复运转的系统**

#### 19.6 现场演示（15 min）
- 演示"输入一条爆款视频链接 → 拆解团队出拍摄手册 → 生产团队出脚本初稿"
- 演示"人工验收 + 修改"环节
- 演示失败模式：转写错、镜头分析偏、脚本生成走偏

#### 19.7 三哥 AI 视频相关笔记引用（5 min）
- 三哥 wiki 内 `AI视频处理与自动化技能开发演示` 笔记记录了：
  - 字幕烧入 vs 软字幕的选择
  - 音频语言转换的复杂度
  - FFmpeg 命令的常见错误
  - 违禁词处理（本地违禁词表 + 第一条提示词处理）
- 三哥 wiki 内 `基于AI的四步爆款内容创作工作流` 笔记记录了：
  - 纯模仿 vs 纯原创的痛点
  - 4 个 Skill 协作的全流程
  - 8 维度对标爆款拆解
- **本节课可以直接引用三哥笔记作为补充材料**

#### 19.8 安全与合规清单（5 min）
- ✅ 必须有的：人工验收节点、平台授权检查、版权边界
- ❌ 绝对禁止的：自动发布、自动评论、自动搬运、刷量
- ⚠️ 灰区：仿拍建议（用结构 vs 抄画面）

### 教学要点
- ✅ **两支团队的设计是核心**——比"做一条视频"重要
- ✅ 强调"学习-生产-复盘"的闭环思维
- ✅ 引用三哥真实笔记，可信度更高
- ❌ 不要演示"全自动无人值守"——必须有人工

### 课后作业
- 组建自己的两支 AI 团队（写团队设计文档）
- 跑通 1 个"拆解 → 生产"全流程
- 输出：1 份拍摄手册 + 1 条视频初稿

## 第 20 章 · 自媒体不只是靠努力

| 项 | 内容 |
|---|---|
| **课时** | 90 min |
| **难度** | ★★★★ |
| **核心目标** | 把"内容生产"变成"增长闭环" |
| **学习成果** | 1 套完整自媒体 SOP |

### 章节内容

#### 20.1 自媒体的真相（10 min）
- 努力 ≠ 增长
- 三类失败：
  - **生产不出**：日更 3 天就断更
  - **生产出但没人看**：定位错 / 平台不友好
  - **有人看但不涨粉**：转化路径断

#### 20.2 增长闭环 5 环（25 min）
```
定位 → 内容 → 流量 → 转化 → 复盘
 ↑                            │
 └────────────────────────────┘
```

| 环 | 关键问题 | AI 能做什么 |
|---|---|---|
| 定位 | 给谁看？凭什么看？ | 竞品分析、用户画像 |
| 内容 | 选题/脚本/视觉/剪辑 | 全流程自动化（参第 19 章） |
| 流量 | 标题/封面/标签/发布 | AI 优化 + 人工决策 |
| 转化 | 评论区/私信/直播 | 半自动回复 + 人工跟进 |
| 复盘 | 数据/反馈/迭代 | AI 汇总 + 人工判断 |

#### 20.3 团队设计（20 min）
- **定位 Agent**：竞品分析 + 差异化建议
- **内容 Agent**：复用第 19 章团队
- **流量 Agent**：标题 + 封面 + 标签 + 发布时间
- **转化 Agent**：评论分类 + 私信模板 + 跟进清单
- **复盘 Agent**：周报 + 月报 + 调整建议

#### 20.4 现场演示（15 min）
- 演示一个 30 天自媒体闭环运营
- 演示失败模式：定位漂移、内容断更、转化路径断

#### 20.5 三条铁律（5 min）
- **定位先于内容**：定位错，内容再好也没用
- **复盘先于生产**：不迭代的努力是重复劳动
- **合规先于增长**：被封号了一夜回到解放前

### 教学要点
- ✅ 强调**"定位 + 复盘"是常被忽略的环节**
- ❌ 不要演示"日更 10 条"——质量比数量重要

### 课后作业
- 写出自己的自媒体定位（1 页纸）
- 跑 30 天，统计"涨粉 + 转化"两指标

## 第 21 章 · WorkBuddy 做 GEO 专家

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 让 AI 帮你在 AI 搜索里被"找到" |
| **学习成果** | 1 份 GEO 优化方案 |

### 章节内容

#### 21.1 GEO 是什么（10 min）
- **GEO**：Generative Engine Optimization
- 区别于 SEO：传统 SEO 优化"百度排名"，GEO 优化"AI 搜索答案"
- 关键问题：当用户问 ChatGPT/豆包/文心「XX 怎么做」，你的品牌会不会被提到？

#### 21.2 GEO vs SEO（10 min）
| 维度 | SEO | GEO |
|---|---|---|
| 优化对象 | 网页排名 | AI 答案引用 |
| 内容形式 | 关键词密度 | 结构化事实 |
| 评估方式 | 排名 | AI 引用率 |
| 工具 | 站长工具 | AI 搜索测试 |

#### 21.3 团队设计（20 min）
- **关键词 Agent**：监控"AI 搜索里你的行业被怎么问"
- **内容生成 Agent**：按 GEO 原则写结构化内容
- **分发 Agent**：多平台同步 + Schema 标记
- **效果评估 Agent**：定期问 AI 你的品牌 / 行业，看回答变化

#### 21.4 现场演示（15 min）
- 跑 1 次"问 AI 关于自己行业的 5 个问题"
- 对比"优化前 vs 优化后"答案变化
- 演示失败模式：AI 答案随机、内容没人看

#### 21.5 边界（5 min）
- **不刷量**——GEO 不是灌水
- **不操纵 AI**——所有内容必须真实
- **不只为 AI 写**——还是为人写

### 教学要点
- ✅ 让学员**问 AI 关于自己行业的问题**，建立直观感受
- ❌ 不要演示"AI 投毒"——边界感差

### 课后作业
- 跑 1 次"AI 搜索关于自己行业的 10 个问题"
- 写出 GEO 优化方案（1 页纸）
