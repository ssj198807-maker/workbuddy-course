# 第一篇 · 使用手册 · 课纲

> **本篇目标**：让"没碰过 WorkBuddy"的人，10 章之后能独立用 AI 完成自己的日常工作。
> **课时总计**：6.5 小时（10 节 × 平均 40 min）
> **难度**：★ 到 ★★★
> **核心交付物**：一个跑通的工作区 + 第一个自动化任务

## 第 1 章 · 初识 WorkBuddy

| 项 | 内容 |
|---|---|
| **课时** | 30 min |
| **难度** | ★ |
| **核心目标** | 理解"WorkBuddy 不是聊天工具，是 AI 工作系统" |
| **学习成果** | 能在自己电脑上打开 WorkBuddy 并登录 |
| **关键概念** | 任务（Task）、技能（Skill）、专家（Agent）、专家团（Team） |

### 章节内容

#### 1.1 WorkBuddy 是什么（10 min）
- **是什么**：一个本地 AI 工作台，不是另一个 ChatGPT 网页
- **不是什么**：不是聊天工具、不是单纯的 Agent 平台
- **三个关键词**：
  - **任务（Task）**：今天要交付的成果物
  - **技能（Skill）**：任务需要的具体能力（写文案 / 查天气 / 改 PDF）
  - **专家（Agent）**：调度 Skill 完成任务的"虚拟员工"
  - **专家团（Team）**：多个 Agent 协作完成复杂任务

#### 1.2 为什么需要它（10 min）
- 对比三种 AI 使用方式：
  - **网页聊天**：用完就忘、没沉淀
  - **代码 Agent**：门槛高、非技术人用不了
  - **WorkBuddy**：任务驱动、Skill 可复用、结果可验收
- 一个真实故事：把"我今天要做周报"从"打开 ChatGPT 写两句"升级为"调度三个 Skill 自动生成周报初稿"

#### 1.3 现场演示（10 min）
- 打开 WorkBuddy，演示一个完整任务流程
- 重点不是演示结果，是演示"任务说明"长什么样

### 教学要点
- ✅ 必须让学员**理解"任务说明"是核心**，不是提示词
- ❌ 不要陷入"和 ChatGPT 比哪个强"的讨论

### 课后作业
- 安装 WorkBuddy（参考第 2 章）
- 写下你自己今天要做的 3 个任务（不要写"写文案"，要写"基于本周 5 场客户会议记录生成周报"）

## 第 2 章 · 下载、安装、登录与更新

| 项 | 内容 |
|---|---|
| **课时** | 30 min |
| **难度** | ★ |
| **核心目标** | 全平台安装、登录、保持最新 |
| **学习成果** | 桌面端 + 移动端都能用 |

### 章节内容

#### 2.1 平台选择（5 min）
- **桌面端**：macOS / Windows / Linux（推荐作为主战场）
- **移动端**：iOS / Android（用于临时任务）
- **Web 端**：应急用，不推荐长期使用

#### 2.2 下载与安装（10 min）
- 官方下载地址 + 注意事项
- **国内网络加速方案**（如需要）
- 常见安装失败：
  - macOS「无法打开，因为无法验证开发者」→ 系统设置 → 隐私与安全性 → 仍要打开
  - Windows SmartScreen 拦截 → 更多信息 → 仍要运行

#### 2.3 登录与多端同步（10 min）
- 账号注册（手机号 / 邮箱）
- 首次登录配置（语言、模型选择、连接器授权）
- **多端同步原理**：任务、技能、连接器都同步，但本地文件不自动同步

#### 2.4 更新机制（5 min）
- 自动更新 vs 手动更新
- 大版本更新前的"技能兼容性"检查

### 教学要点
- ✅ 现场帮助学员**解决安装报错**，不要只演示成功路径
- ❌ 不要讲"如何破解"或"如何换源"等灰色话题

### 课后作业
- 完成桌面端 + 移动端登录
- 截图保存，作为"环境就绪"凭证

## 第 3 章 · 主界面、任务与工作区

| 项 | 内容 |
|---|---|
| **课时** | 45 min |
| **难度** | ★ |
| **核心目标** | 理解"任务"和"工作区"的关系 |
| **学习成果** | 能搭建自己的工作区结构 |

### 章节内容

#### 3.1 主界面四区域（10 min）
- **左栏**：工作区列表（个人/团队/项目）
- **中栏**：任务流（今日 / 本周 / 全部）
- **右栏**：当前任务详情（对话 / 文件 / 进度）
- **顶栏**：全局搜索、新建任务、连接器状态

#### 3.2 任务的三种状态（10 min）
- **进行中**：正在被 AI 执行
- **待验收**：AI 跑完，等你确认
- **已完成**：已确认，归档到工作区
- **关键认知**：待验收 ≠ 已完成，**不验收永远不算交付**

#### 3.3 工作区的搭建（15 min）
- 推荐结构（按角色）：
  - **个人区**：日常任务、灵感记录
  - **项目区**：每个项目一个子工作区
  - **学习区**：课程任务、读书笔记
- **不要做**：把所有任务都丢到「默认工作区」

#### 3.4 任务的元信息（10 min）
- 每个任务应有的字段：
  - 标题（动词开头：「整理」而不是「桌面文件」）
  - 任务说明（边界 + 验收）
  - 关联文件
  - 标签（项目 / 类型 / 优先级）
  - 截止时间

### 教学要点
- ✅ 让每个学员**当场搭建自己的工作区**，不要只是看
- ❌ 不要讲"高级筛选"等花式功能，本章重点是基础认知

### 课后作业
- 搭建自己的 3 个工作区（个人 / 项目 / 学习）
- 在每个工作区里新建 1 个真实任务

## 第 4 章 · 快速完成第一个 WorkBuddy 任务

| 项 | 内容 |
|---|---|
| **课时** | 45 min |
| **难度** | ★★ |
| **核心目标** | 端到端跑通一个真实任务 |
| **学习成果** | 掌握"任务说明 4 要素" |

### 章节内容

#### 4.1 任务说明 4 要素（15 min）
**本节是全章重点，是整个蓝皮书的"语言基础"**。

| 要素 | 作用 | 写错的后果 |
|---|---|---|
| **目标** | 告诉 AI 交付什么 | AI 自己发挥方向 |
| **材料** | 给 AI 输入什么 | AI 凭空编造 |
| **格式** | 输出长什么样 | 格式不达标返工 |
| **边界** | 不能做什么 | AI 做错（自动发邮件/删文件） |

#### 4.2 第一个任务演示（15 min）
任务：「帮我把桌面『杂项』文件夹按类型整理」
- **目标**：按文件类型分到子文件夹，未识别类型放进 `_待人工分类`
- **材料**：桌面『杂项』文件夹路径
- **格式**：每个子文件夹用类型命名（图片/文档/视频/其他）
- **边界**：**不要移动任何 .docx/.xlsx 文件**（业务文件），**不删除任何文件**

#### 4.3 验收与复盘（15 min）
- 验收三档：
  - ✅ **能**：所有文件按类型正确分类
  - ❌ **不能**：误移动了 .docx 文件
  - ⚠️ **待定**：未识别类型数量过多（>20%）
- 复盘：任务说明哪里写得好/写得不好

### 教学要点
- ✅ 让学员**自己写一个任务说明**，当场给讲师看
- ❌ 不要演示"花式提示词技巧"，本章只讲"任务说明"

### 课后作业
- 用任务说明 4 要素，重写第 1 章作业里的 3 个任务
- 至少完成 1 个真实任务（用 WorkBuddy 实际跑通）

## 第 5 章 · 加载一个真正用得上的 Skill

| 项 | 内容 |
|---|---|
| **课时** | 45 min |
| **难度** | ★★ |
| **核心目标** | 理解"Skill 是能力的封装" |
| **学习成果** | 安装并调通 1-2 个常用 Skill |

### 章节内容

#### 5.1 Skill 是什么（10 min）
- **定义**：把"提示词 + 工具调用 + 输入输出校验"打包成一个可复用的能力
- **类比**：手机里的 App（Skill）vs 系统自带功能（裸 LLM）
- **三类 Skill**：
  - 官方推荐（维护好）
  - 社区贡献（质量参差）
  - 自己创建（第三篇第 22 章重点讲）

#### 5.2 找 Skill 的方法（10 min）
- WorkBuddy Skill 市场
- 关键词搜索 vs 场景搜索
- **看评价数 + 最近更新时间**两个指标

#### 5.3 必装 Skill 清单（15 min）
按角色推荐：
- **通用**：
  - 「文件批量整理」——本地文件分类
  - 「网页内容抓取」——网页/公众号抓取
  - 「图片压缩加水印」——发布前处理
  - 「多平台文案」——一稿三端
- **内容**：
  - 「错别字检查」——发布前自查
  - 「降低 AI 腔」——内容去 AI 味
  - 「标题优化」——10 个候选标题
- **数据**：
  - 「Excel 自动分析」——表格问答
  - 「PDF 转 Word/Excel」——文档格式转换

#### 5.4 现场安装演示（10 min）
- 安装 1 个「文件批量整理」Skill
- 跑一遍第 4 章那个任务，对比"裸 LLM"和"用 Skill"的差异

### 教学要点
- ✅ 重点讲**如何判断一个 Skill 好不好用**
- ❌ 不要陷入"装 50 个 Skill"的炫耀，学生容易迷失

### 课后作业
- 安装 5 个 Skill，至少跑通 1 个真实场景
- 给每个 Skill 写一句「使用心得」（好/不好用，用在哪）

## 第 6 章 · 专家和专家团

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★ |
| **核心目标** | 从"用工具"升级到"调度团队" |
| **学习成果** | 理解"任务 → 团队"的思维跃迁 |

### 章节内容

#### 6.1 专家（Agent）是什么（15 min）
- **类比**：一个能调度多个 Skill 的"虚拟员工"
- **示例**：「秘书小张」Agent = 文档处理 Skill + 日程管理 Skill + 邮件 Skill
- **关键**：Agent 不等于 LLM，Agent 是"调度 LLM + Skill"的协调器

#### 6.2 什么时候用 Agent（10 min）
- **不需要 Agent**：单一任务、单一 Skill 能搞定
- **需要 Agent**：
  - 任务需要 3 个以上 Skill
  - 任务有明确分工（谁先做、谁后做、谁验收）
  - 任务需要持续运行（每天早上自动跑）

#### 6.3 专家团（Team）是什么（20 min）
- **核心概念**：把多个 Agent 组建成一支"AI 团队"
- **三种典型结构**：
  - **流水线型**：Agent A 做 X → Agent B 做 Y → Agent C 验收
  - **协作型**：3 个 Agent 并行处理同一任务的不同部分
  - **层级型**：团长 Agent 调度 3 个兵卒 Agent
- **案例**：「短视频生产团队」= 选题 Agent + 脚本 Agent + 视觉 Agent + 剪辑 Agent

#### 6.4 现场演示（15 min）
- 演示一个三 Agent 协作完成"客户邮件草拟 + 附件整理 + 日程提醒"
- 重点不是演示结果，是演示"如何拆分任务给不同 Agent"

### 教学要点
- ✅ **本章是整个蓝皮书的"分水岭"**——前面是工具，后面是团队
- ❌ 不要讲太复杂的"多 Agent 协议"（第三篇第 24 章才讲）

### 课后作业
- 设计一个属于自己的 3-Agent 团队（写出来，不一定真实现）
- 团队至少要解决你工作中的 1 个真实痛点

## 第 7 章 · 使用连接器

| 项 | 内容 |
|---|---|
| **课时** | 45 min |
| **难度** | ★★ |
| **核心目标** | 让 AI 能访问外部数据 |
| **学习成果** | 接入 1-2 个连接器，能跑通跨系统任务 |

### 章节内容

#### 7.1 连接器（Connector）是什么（10 min）
- **定义**：让 WorkBuddy 能访问外部系统的"数据通道"
- **类比**：USB 接口——你的电脑要连 U盘/打印机/网线，都得有个接口

#### 7.2 必装连接器清单（15 min）

| 类别 | 连接器 | 用途 |
|---|---|---|
| **办公** | 飞书 / 钉钉 / 企业微信 | 文档、日程、消息 |
| **内容** | 微信公众号 / 头条 | 内容发布 |
| **数据** | 飞书表格 / 钉钉表格 | 数据存储 |
| **代码** | GitHub / GitLab | 代码托管 |
| **通用** | Webhook / HTTP | 任何 API |

#### 7.3 接入流程（10 min）
- OAuth 授权 → 权限确认 → 测试连通性
- **安全红线**：连接器授权时**只勾选必要的权限**

#### 7.4 现场演示（10 min）
- 接入飞书连接器
- 演示一个跨系统任务：「把飞书文档里上周的会议纪要转成本地 Markdown 笔记」

### 教学要点
- ✅ 强调**"最小权限原则"**——能少勾选就少勾选
- ❌ 不要讲"自建连接器"（第 9 章才讲）

### 课后作业
- 接入 2 个连接器（飞书 + 任意 1 个）
- 跑通 1 个跨系统任务

## 第 9 章 · 接入外部 API

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 解决"WorkBuddy 没内置的连接器" |
| **学习成果** | 自己建 1 个 API 连接器 |

### 章节内容

#### 9.1 什么时候需要自建 API（10 min）
- **场景**：你要连的外部系统 WorkBuddy 没提供连接器
- **典型**：自家公司的 CRM、ERP、内部数据库

#### 9.2 API 接入四步法（20 min）
```
1. 找文档   → 2. 申请 Key   → 3. 测接口   → 4. 配连接器
```
- 文档里必看的 5 个字段：
  - 端点（Endpoint）
  - 方法（GET/POST）
  - 鉴权（API Key / OAuth）
  - 请求体（Request Body）
  - 响应体（Response Body）

#### 9.3 三个常见 API 实操（20 min）
- **天气 API**：最简单的 GET 请求
- **飞书机器人 Webhook**：POST + JSON
- **公司 CRM API**：（以学员自己公司为例）实战演练

#### 9.4 故障排查（10 min）
- 401：鉴权失败
- 403：权限不足
- 404：端点错
- 429：调用太频繁
- 500：服务器问题

### 教学要点
- ✅ 让学员**自己公司 API** 做案例，不只是"天气 API"
- ❌ 不要讲 GraphQL / WebSocket 等高级协议

### 课后作业
- 自己公司的 1 个 API → 接入 WorkBuddy
- 跑通 1 个真实任务

## 第 10 章 · 自动化任务

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★ |
| **核心目标** | 让任务"到点自动跑" |
| **学习成果** | 配 2-3 个定时任务 |

### 章节内容

#### 10.1 自动化任务类型（10 min）
- **定时型**：每天 9 点跑
- **触发型**：某个事件触发（如新邮件到达）
- **链式型**：A 跑完自动跑 B

#### 10.2 自动化任务 4 要素（15 min）
- **触发条件**：什么时候跑
- **执行内容**：跑什么任务
- **失败处理**：跑失败怎么办（重试？通知？）
- **日志保存**：跑的过程要不要存

#### 10.3 必配自动化任务清单（20 min）
- **每日资讯汇总**：每天早 9 点推送 AI 行业新闻
- **桌面整理**：每周日晚自动整理桌面
- **会议提醒**：提前 15 分钟推送到 IM
- **周报自动生成**：周五下午自动汇总本周任务

#### 10.4 现场演示 + 安全红线（15 min）
- 配 1 个"每日资讯汇总"任务
- **必讲的安全红线**：
  - 自动化任务**绝对不能自动发邮件/发布内容/删除文件**
  - 所有"外发"操作必须有人工确认节点
  - 自动化任务必须配"失败通知"——跑挂了不能不知道

### 教学要点
- ✅ 强调**"自动化 ≠ 不管"**，要有"运行日报"
- ❌ 不要演示"全自动发布"——这是蓝皮书反模式

### 课后作业
- 配 1 个定时型 + 1 个触发型自动化任务
- 给每个任务配"失败通知"和"运行日志"

### 学员走出第一篇应该具备的能力
