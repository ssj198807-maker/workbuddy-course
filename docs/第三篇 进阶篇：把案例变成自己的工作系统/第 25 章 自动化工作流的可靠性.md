## 第 25 章 · 自动化工作流的可靠性

| 项 | 内容 |
|---|---|
| **课时** | 60 min |
| **难度** | ★★★★ |
| **核心目标** | 让自动化任务"敢睡个安稳觉" |
| **学习成果** | 1 份故障排查手册 + 1 套监控告警配置 |

### 章节内容

#### 25.1 自动化的 5 大风险（10 min）

| 风险 | 后果 | 频率 |
|---|---|---|
| **接口失效** | API 改版 / 平台限流 | 高 |
| **数据错误** | 输入脏数据 | 中 |
| **逻辑漏洞** | 边界条件没处理 | 中 |
| **资源耗尽** | Token / 配额用完 | 中 |
| **外部依赖** | 平台封号 / 服务停机 | 低 |

#### 25.2 可靠性设计 4 原则（20 min）

```
1. 幂等性    → 重复跑结果一样
2. 可重试    → 失败能自动重试
3. 可降级    → 关键路径挂了能用备选
4. 可观测    → 出问题能立刻知道
```

#### 25.3 故障排查流程（20 min）
```
告警 → 定位 → 修复 → 复盘 → 加防御
```

| 步 | 关键动作 | 工具 |
|---|---|---|
| 告警 | 配置多渠道（飞书/邮件/短信） | WorkBuddy 监控 |
| 定位 | 看日志 + 链路追踪 | 日志平台 |
| 修复 | 临时方案 + 永久方案 | - |
| 复盘 | 写"事后报告" | 文档 |
| 加防御 | 加测试 + 加监控 + 加重试 | - |

#### 25.4 常见故障案例（10 min）
- **案例 1：自动化任务跑了 100 次，突然全失败** → API Key 过期
- **案例 2：内容发布失败，重复跑导致重复发布** → 缺幂等设计
- **案例 3：夜间任务挂到天亮没人知道** → 没配告警
- **案例 4：Token 用完整个系统停摆** → 缺配额监控

### 教学要点
- ✅ 强调**"自动化不是不用管，是换一种管法"**
- ❌ 不要演示"全自动无人值守"

### 课后作业
- 写出 1 份"我的故障排查手册"
- 至少包含：5 类故障 + 4 类应对 + 3 条复盘要点

## 第三篇总结

### 学员走出第三篇应该具备的能力
- ✅ 自创 1 个 Skill（含完整设计 + 跑通 3 个场景）
- ✅ 设计 1 个多 Agent 系统（含架构图、消息流、失败处理）
- ✅ 配 1 套监控告警机制
- ✅ 写 1 份故障排查手册

### 学员走出第三篇不应该有的错误认知
- ❌ "多 Agent 越多越好"
- ❌ "自动化是无人值守"
- ❌ "我的 Skill 完美了，不需要迭代"
