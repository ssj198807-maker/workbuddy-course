### 章节内容

#### 24.1 多 Agent 系统的本质（15 min）
- **为什么需要"多 Agent"而不是"一个大 Agent"**：
  - 单一 Agent 上下文窗口有限
  - 单一 Agent 任务多了容易"精神分裂"
  - 多 Agent 可以并行 + 专业化
- **多 Agent ≠ 多 Skill**：
  - Skill 是能力
  - Agent 是调度能力的协调器
  - 多 Agent 是协调器的协调

#### 24.2 三种多 Agent 架构（30 min）

```
1. 流水线型（Pipeline）
   Agent A → Agent B → Agent C → Agent D
   适合：流程固定的场景（如：内容生产流水线）

2. 协作型（Collaborative）
   ┌→ Agent A ─┐
   ├→ Agent B ─┼→ 协调器 → 输出
   └→ Agent C ─┘
   适合：多视角决策（如：投资分析）

3. 层级型（Hierarchical）
        团长 Agent
        /    |    \
   兵卒A  兵卒B  兵卒C
   适合：复杂任务分解（如：项目管理）
```

#### 24.3 消息协议与状态管理（20 min）
- 消息传递模式：
  - **同步**：Agent A 调 Agent B 等待结果
  - **异步**：Agent A 投递，Agent B 空闲时取
  - **广播**：团长发指令，所有兵卒收到
- 状态管理：
  - 共享状态（黑板模式）
  - 消息队列（事件驱动）
  - 数据库（持久化）

#### 24.4 失败处理与兜底（20 min）
- 三种失败：
  - **单 Agent 失败**：重试 + 跳过 + 告警
  - **消息丢失**：幂等设计 + 重投
  - **整体死锁**：超时机制 + 死锁检测
- **关键设计**：所有外部副作用必须**幂等**（重复执行结果一致）

#### 24.5 监控与可观测（20 min）
- 三类信号：
  - **业务信号**：任务成功率、平均耗时
  - **系统信号**：Agent 健康度、队列长度
  - **成本信号**：Token 消耗、API 调用次数
- 监控方式：
  - 日志：每个 Agent 的输入/输出/决策
  - 链路追踪：消息从进入到输出的完整路径
  - 告警：异常时通知人工

#### 24.6 现场演示（10 min）
- 设计一个 3-Agent 的"客户问题分类 + 处理"系统
- 演示失败模式：Agent 死循环、消息丢失、状态错乱

### 教学要点
- ✅ **强调"先单后多"**——单 Agent 跑通再上多 Agent
- ✅ 引用三哥多 Agent 笔记作为参考
- ❌ 不要陷入"协议设计"细节——本章是设计思维，不是工程实现
