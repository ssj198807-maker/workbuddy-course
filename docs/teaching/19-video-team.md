# 第一节 · 思维跃迁（60 min）

---

## 1. 视频工作的真相（10 min）

### 1.1 开场提问（互动节点 1，3 min）

讲师问题：

> "做一条 1 分钟的口播短视频，从选题到发布，你估算要多久？"

让 3-5 个学员报答案（通常 4-15 小时都有）。

讲师回应（**不要直接公布答案，先听学员说**）：

> "大家估算差不多——**但我们今天不是来学'怎么快一点'，是来学'怎么用两支 AI 团队把这件事拆开做'。**"

### 1.2 视频工作的全流程拆解（5 min）

画一张图（用白板 / 投屏）：

```
一条短视频 = 选题 + 脚本 + 分镜 + 视觉 + 剪辑 + 标题封面 + 发布 + 复盘
真人耗时    = 1-2h  2-3h  1h   3-5h  2-3h  1h       0.5h  0.5h
                            ===============
                            这段最痛
```

讲师话术：

> "其中**视觉 + 剪辑是最痛**的——3-5 小时，AI 团队能压缩到 30 分钟内。
> 但**关键不是压缩单个环节**，而是**让两支团队协作**——一支负责生产，一支负责学习。"

### 1.3 蓝皮书核心结论（2 min）

讲师话术（**板书/投屏高亮**）：

> "**视频生成团队解决'今天怎么做一条出来'**。
> **爆款拆解团队解决'为什么别人那条能火，我能学到什么'**。
> **一个负责生产，一个负责学习，组合起来才有持续迭代的可能。**"

---

## 2. 为什么需要两支团队（10 min）

### 2.1 单一团队的 5 大局限（5 min）

| 局限 | 表现 | 后果 |
|---|---|---|
| **只能做，不能学** | 跑 100 条还是同水平 | 越做越累 |
| **没有外部参照** | 不知道行业爆款长啥样 | 自嗨 |
| **没有数据反馈** | 发了不知道为啥火/为啥不火 | 重复犯错 |
| **没有迭代机制** | 一次性的生产 | 越做越水 |
| **没有知识沉淀** | 经验都在脑子里 | 团队换了人重来 |

### 2.2 两支团队的核心差异（5 min）

| 维度 | 视频生产团队 | 爆款拆解团队 |
|---|---|---|
| **目标** | 做一条视频 | 学一条爆款 |
| **产出** | 视频文件 | 拍摄手册 |
| **节奏** | 每天/每周 | 每周/每月 |
| **角色数** | 7 个 | 3 个 |
| **核心技能** | 文案/视觉/剪辑 | 抓取/转录/分析 |
| **失败模式** | 视频质量差 | 拆解偏题 |

### 2.3 现场互动（互动节点 2，1 min）

讲师问题：

> "如果你只能先做一支团队，你会先做哪支？为什么？"

**参考答**：
- 先做**生产**——解决"今天能不能产出"
- 先做**拆解**——解决"为什么我做的没人看"

讲师话术（**不要直接给答案**）：

> "看你当下的痛——如果生产效率低，先做生产；如果你做了一堆没流量，先做拆解。
> **但完整路径是两支都要做**——蓝皮书第 19 章的核心就是两支团队都讲。"

## 3. 视频生产团队设计（30 min）

### 3.1 7 个 Agent 角色详解（15 min）

**逐个讲解，每个角色配一个真实场景示例**：

#### 角色 1：阿刷（团长）

| 项 | 内容 |
|---|---|
| **职责** | 任务调度、流程编排、结果汇总 |
| **类比** | 项目经理 / 制片人 |
| **关键能力** | 任务拆分、状态跟踪、异常处理 |
| **失败模式** | 不会调度，Agent 之间传错任务 |

**示例任务说明**：
```
【任务】调度生产团队完成一条 1 分钟口播视频

【调度规则】
- 先调阿热点确定选题
- 选题确定后调阿脚本写脚本
- 脚本完成后调阿分镜
- 分镜确认后并行调阿渲染
- 渲染完成后调阿剪辑合成
- 剪辑完成后调阿发布生成标题封面

【边界】
- 每个环节必须人工验收才能进下一环
- 任何环节失败立即停止并通知
```

#### 角色 2：阿热点

| 项 | 内容 |
|---|---|
| **职责** | 监控热点、推荐选题 |
| **类比** | 选题策划 |
| **关键能力** | 实时监控热点 + 行业信号 |
| **失败模式** | 推的热点是 3 天前的 / 推的热点跟账号定位不符 |

**示例数据源**：
- 微博热搜
- 抖音热点榜
- 知乎热榜
- 自定义关键词监控

#### 角色 3：阿脚本

| 项 | 内容 |
|---|---|
| **职责** | 写脚本、改脚本 |
| **类比** | 文案策划 |
| **关键能力** | 爆款脚本结构 + 改稿能力 |
| **失败模式** | AI 腔 / 数据虚构 / 结构拖沓 |

**爆款脚本 3 结构**（讲师板书）：
```
1. 钩子（0-5s）：抓眼球
2. 痛点（5-30s）：用户共鸣
3. 方案（30-60s）：给方法
```

#### 角色 4：阿分镜

| 项 | 内容 |
|---|---|
| **职责** | 把脚本拆成镜头 |
| **类比** | 导演 |
| **关键能力** | 镜头语言 + 视觉化表达 |
| **失败模式** | 镜头语言错误 / 不会用景别 |

**镜头 5 要素**（讲师板书）：
- 景别（中景/特写/远景）
- 运镜（推/拉/摇/移）
- 时长（建议 3-5s 一个镜头）
- 主体（人/物/场景）
- 字幕（关键句必须上字幕）

#### 角色 5：阿渲染

| 项 | 内容 |
|---|---|
| **职责** | 生成视觉素材 |
| **类比** | 摄影 / 平面设计 |
| **关键能力** | 文生图 / 图生视频 |
| **失败模式** | AI 生图风格不统一 / 镜头与脚本不符 |

**关键原则**：
- ✅ 必须先有**风格参考图**
- ✅ 必须先有**角色一致性参考**
- ❌ 不要"自由发挥"——AI 简化 ≠ 客户原意

#### 角色 6：阿剪辑

| 项 | 内容 |
|---|---|
| **职责** | 合成 + 字幕 + 配乐 |
| **类比** | 后期剪辑 |
| **关键能力** | ffmpeg + 剪辑模板 |
| **失败模式** | 字幕错位 / 音画不同步 / 配乐盖过人声 |

**讲师现场提示**（基于一线实战经验）：

> - 字幕类型：硬字幕（烧入视频）vs 软字幕（外挂）
> - 音频语言转换复杂度高：会增加技能复杂度
> - 国产模型生成文档"不够丰富和说人话"
> - **违禁词处理**：本地放违禁词表 + 第一条提示词要求加星号

#### 角色 7：阿发布

| 项 | 内容 |
|---|---|
| **职责** | 标题 + 标签 + 封面 + 多平台 |
| **类比** | 运营 |
| **关键能力** | 平台规则理解 + 多平台同步 |
| **失败模式** | 标题党被限流 / 跨平台数据冲突 |

**蓝皮书铁律**（讲师**必须高亮**）：

> **默认不要直接自动发布！**
> **除非账号、素材、标题、合规边界都已经过人工确认。**

### 3.2 6 步生产流程图（10 min）

讲师在白板/投屏画图：

```
         选题        脚本         分镜         视觉         剪辑         发布
   阿热点 → 阿脚本 → 阿分镜 → 阿渲染 → 阿剪辑 → 阿发布
            ↓           ↓           ↓           ↓           ↓
       人工验收   人工验收    人工验收    人工验收    人工验收
                                                       ↑
                                                ★ 必须有这一环
```

讲师话术：

> "**每个箭头下面都有'人工验收'**——这是蓝皮书铁律。
> **任何环节不通过，整条流程就停。**不要追求'全自动'，追求'可控的半自动'。"

### 3.3 现场演示 1：跑通"一条视频"（5 min）

**演示前准备**：
- 已登录 WorkBuddy
- 7 个 Agent 已配置（哪怕是简化版）
- 1 个真实选题任务

**演示步骤**：
1. 给阿热点下任务：「给我 5 个 AI 视频相关选题」
2. 验收：选 1 个
3. 给阿脚本下任务：「基于选题写 60s 口播脚本」
4. 验收：调整 2-3 处（**演示 AI 腔要去掉**）
5. 跳过阿分镜/阿渲染/阿剪辑（课堂时间不够，**但要提一下**会怎么跑）
6. 给阿发布下任务：「生成 5 个标题 + 3 个标签 + 1 个封面文案」
7. 验收：选 1 个标题

**演示要点**：
- ✅ 演示**真实的 AI 腔问题**（"在这个时代..."、"让我们一起..."）
- ✅ 演示**人工怎么改**
- ❌ 不要演示"一气呵成全自动"——那不是真的

## 5. 爆款视频拆解团队设计（15 min）

### 5.1 为什么需要拆解团队（5 min）

讲师话术：

> "光会生成还不够。
> 内容创作者真正需要的是理解'为什么别人能爆'，把一条爆款视频拆成可以参考的操作手册。"

**拆解 vs 模仿**（**重点强调**）：

| 维度 | 模仿 | 拆解 |
|---|---|---|
| **目的** | 抄一个 | 学结构 |
| **产出** | 一条一样的 | 一本手册 |
| **边界** | 容易侵权 | 不侵权 |
| **价值** | 短期流量 | 长期能力 |

**蓝皮书原话**（**必须念给学员听**）：

> "**视频下载和分析要遵守平台条款、版权授权和合理使用范围。
> 拆解的目的应该是学习结构和方法，不是搬运原视频。**"

### 5.2 3 个 Agent 角色（10 min）

#### 角色 1：阿爆（团长）

| 项 | 内容 |
|---|---|
| **职责** | 拆解总控、流程编排 |
| **类比** | 复盘分析师 |
| **关键能力** | 任务调度 + 输出汇总 |
| **失败模式** | 不会拆解维度 |

#### 角色 2：小凯（音频处理）

| 项 | 内容 |
|---|---|
| **职责** | 音频处理与转录 |
| **类比** | 速记员 |
| **关键能力** | ffmpeg + ASR |
| **工具** | ffmpeg（提取音频）+ ASR（语音转文字） |
| **失败模式** | 转写错 / 漏转 / 多语种处理失败 |

**示例任务**：
```
【任务】从【视频路径】提取音频并转录成文案

【步骤】
1. ffmpeg 提取 audio.mp3
2. ASR 转写完整口播文案
3. 标出每句话的时间戳

【边界】
- 不修改视频
- 保留原始音频做备份
- 转写不准的标"待确认"
```

#### 角色 3：小淼（视频理解）

| 项 | 内容 |
|---|---|
| **职责** | 视频理解与镜头裁切 |
| **类比** | 镜头分析师 |
| **关键能力** | 视频理解 API + 镜头分析 |
| **工具** | 视频理解 API + ffmpeg 裁切 |
| **失败模式** | 镜头分析偏 / 不会用景别术语 |

**示例分析维度**：
- 景别分布（中景/特写/远景占比）
- 镜头时长（平均多少秒）
- 运镜方式（推/拉/摇/移）
- 转场方式（硬切/淡入淡出/转场特效）
- 色调风格（冷色/暖色/高对比）
- 字幕风格（位置/字体/动效）

### 5.3 3 步拆解流程（5 min）

```
1. 视频下载（API → Playwright → yt-dlp 三层降级）
   ↓
2. 音频提取 + 文案转写
   ↓
3. 视频理解 + 镜头语言分析
```

**3 层降级**（**重点讲**）：

| 优先级 | 方法 | 适用 |
|---|---|---|
| 第 1 层 | 官方 API | 平台有开放 API |
| 第 2 层 | Playwright | 平台有网页但无 API |
| 第 3 层 | yt-dlp | 上述都失败 |

讲师话术：

> "**视频下载是整个拆解流程最复杂的一步**——平台反爬、限速、登录墙都让这一步最容易挂。
> 所以设计**三层降级**——任何一层成功就继续。"

**合规边界**（**必须强调**）：

> "**必须遵守平台条款、版权授权、合理使用范围。**
> **拆解是'学结构'，不是'搬运原视频'。**
> **仿拍建议必须基于已公开的镜头规律，不是原视频画面。**"

### 5.4 现场演示 2：拆解一条爆款（10 min）

**演示前准备**：
- 准备 1 条抖音/视频号爆款链接
- 3 个 Agent 已配置
- 三层降级下载链路已搭好

**演示步骤**：
1. 给阿爆下任务：「拆解这条爆款视频」
2. 阿爆调度小凯转录音频 → 演示转写结果
3. 阿爆调度小淼分析镜头 → 演示分析报告
4. 阿爆汇总输出"拍摄手册"

**输出示例**（**演示时投屏给学员看**）：

```markdown
# 爆款视频拆解报告

## 基础信息
- 视频链接：xxx
- 标题：xxx
- 时长：xx 秒
- 发布时间：xxx
- 点赞：xxx

## 文案转写
- 00:00-00:05：「钩子：xxx」
- 00:05-00:30：「痛点：xxx」
- 00:30-00:60：「方案：xxx」

## 镜头分析
- 景别分布：中景 60% / 特写 30% / 远景 10%
- 平均镜头时长：3.5 秒
- 主要运镜：固定 + 推镜
- 字幕风格：底部白字黑边

## 仿拍建议
1. 钩子用"反问"句式（前 3 秒）
2. 痛点列举 3 个具体场景
3. 方案部分用"清单体"展示
4. 镜头多用中景 + 特写切换
5. 字幕全程不消失
```

**演示要点**：
- ✅ 演示**真实转写错误**（学员能看到 AI 不完美）
- ✅ 演示**怎么判断分析质量**（不是看 AI 说啥就信啥）
- ❌ 不要演示"完美拆解"——AI 永远不完美

## 7. 两支团队如何形成闭环（5 min）

### 7.1 闭环图（讲师板书/投屏）

```
爆款视频链接
       ↓
拆解团队：转写、镜头、节奏、仿拍建议
       ↓
形成拍摄手册和内容规律
       ↓
生成团队：热点、脚本、分镜、渲染
       ↓
人工验收 + 发布
       ↓
数据复盘
       ↓
回到拆解
```

讲师话术：

> "**这是专家团比单个工具更有意义的地方。**
> **不只是做一条视频——让'学习、生产、发布、复盘'变成一个可以重复运转的系统。**"

### 7.2 闭环的 4 个关键节点

| 节点 | 关键问题 | 谁负责 |
|---|---|---|
| **学习** | 这条爆款我能学到什么？ | 拆解团队 |
| **生产** | 今天我做一条什么样的？ | 生成团队 |
| **发布** | 这条视频能发吗？ | 人工 + 发布 Agent |
| **复盘** | 这次效果如何？下次怎么改？ | 数据 Agent + 人工 |

### 7.3 闭环跑通的 3 个标志

1. **每周至少拆解 2 条爆款**
2. **每周至少生产 5 条视频**
3. **每月至少 1 次数据复盘**（看哪条爆、哪条没爆、为什么）

## 8. 安全与合规清单（5 min）

### 8.1 ✅ 必须有的（讲师念一遍）

1. **人工验收节点**——每个关键步骤都要有人工确认
2. **平台授权检查**——发布前确认账号正常、平台无异常
3. **版权边界**——拆解是学结构，不搬运原视频
4. **违禁词处理**——本地违禁词表 + 第一条提示词处理
5. **失败通知**——任何环节挂了要立刻知道

### 8.2 ❌ 绝对禁止的（**特别强调**）

1. **自动发布**——所有发布必须人工
2. **自动评论**——绝不自动回复
3. **自动搬运**——绝不直接搬运原视频
4. **刷量**——绝不买量/刷互动
5. **伪造数据**——所有数据必须真实

### 8.3 ⚠️ 灰区

| 行为 | 风险 | 建议 |
|---|---|---|
| 仿拍建议 | 可能被认定"抄袭结构" | 至少改 30% 关键参数 |
| 引用金句 | 可能侵权 | 注明出处 + 不超过 30 字 |
| 主题相似 | 可能被限流 | 加入自己的角度 |

## 9. 学员实操 + 总结（10 min）

### 9.1 学员实操（互动节点 3，5 min）

讲师给学员 1 个真实任务：

```
【实操任务】设计你的两支 AI 团队

【任务】基于你的视频业务场景，设计：
1. 一支视频生产团队（至少 5 个 Agent）
2. 一支爆款拆解团队（至少 3 个 Agent）
3. 团队之间的协作流程

【输出】
- 团队角色清单（每个角色 1 句话职责）
- 协作流程图（5-8 步）
- 验收标准（每个环节的"能/不能/待定"）
- 安全边界（哪些自动、哪些必须人工）

【时间】5 分钟，写在草稿纸或文档里
```

让 2-3 个学员现场分享（**不要让所有人都讲**）。

### 9.2 收尾反思（5 min）

讲师问最后一个问题（**最重要的问题**）：

> "**如果只让你带走一个点，是什么？**"

让 2-3 个学员回答。

**讲师参考答**：
- "AI 团队要**两支**——只做生产不做学习是原地踏步"
- "**每个环节都要有人工验收**——不是全自动"
- "**拆解是学结构不是搬运**——边界感最重要"
- "**闭环跑通**比单次爆款更重要"

### 9.3 课后作业

```
【作业 1：团队设计文档】
为你的视频业务设计 1 支生产团队 + 1 支拆解团队
- 团队角色清单
- 协作流程图
- 验收标准
- 安全边界

【作业 2：跑通 1 个全流程】
- 选 1 条你想模仿的爆款（不搬运）
- 拆解团队出"拍摄手册"
- 生产团队出"脚本初稿"
- 人工验收 + 修改记录

【作业 3：踩坑清单】
- 跑 3 次，记 5 条踩坑
- 每条：踩坑现象 + 原因 + 应对
```

## 附录 · 故障卡（讲师必备）

> 上课时最常碰到的 3 个报错 + 解法。

### 故障 1：视频下载失败
- **现象**：API/Playwright/yt-dlp 三层都失败
- **原因**：平台反爬升级 / 链接失效 / 网络问题
- **解法**：
  1. 检查链接是否有效（手动打开看）
  2. 换条同类型爆款
  3. 通知学员：**不要硬磕同一条**——换条继续

### 故障 2：转写错误率高
- **现象**：转写文案里人名/数字/专业词全错
- **原因**：口音 / 背景音 / 专业术语
- **解法**：
  1. 标"待确认"而不是猜
  2. 用本地 LLM 二次校验
  3. 关键人名/数字必须人工听一遍

### 故障 3：AI 生成的脚本太"AI 腔"
- **现象**："在这个时代..."、"让我们一起..."、"赋能..."
- **原因**：LLM 默认输出模板
- **解法**：
  1. 在任务说明里加禁用词列表
  2. 加 1-2 个反例（"不要像 XX 那样写"）
  3. 人工改 2-3 句示范，AI 学习你的风格
