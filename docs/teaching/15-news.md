## 1. 信息流的三种处理（10 min）

### 1.1 开场互动

讲师问：

> "你每天花多少时间刷信息？真正记住的有多少？"

典型回答：1-3 小时刷，记住 < 10%。

### 1.2 三种处理方式对比

| 方式 | 行为 | 留存率 | 痛点 |
|---|---|---|---|
| **被动接收** | 每天刷 30 min | < 5% | 刷完就忘 |
| **手动整理** | 用工具收藏 | < 15% | 收藏夹吃灰 |
| **AI 推送** | 每天 9 点推 5 条 | > 60% | 配起来有点麻烦 |

讲师话术：

> "**AI 推送是性价比最高的**——但前提是'少而准'。
> **5 条好资讯 > 50 条噪音。**"

## 2. 资讯整合 4 步法（15 min）

### 2.1 4 步流程

```
1. 源筛选   → 2. 内容抓取   → 3. AI 摘要   → 4. 推送通知
```

### 2.2 每步的关键 + 失败模式

| 步 | 工具 | 关键 | 失败模式 |
|---|---|---|---|
| 源筛选 | RSS / API / 爬虫 | 少而精（最多 5 个） | 选了 20 个 → 噪音 |
| 内容抓取 | 网页抓取 Skill | 抓全文 + 去广告 | 抓到一半 / 抓到登录墙 |
| AI 摘要 | LLM | 200 字内 + 3 条关键判断 | 摘要变"读后感" |
| 推送通知 | 飞书 / 邮件 | 固定时间 + 固定格式 | 推送时间错 / 推送失败 |

### 2.3 源筛选的 5/3/1 原则

- **最多 5 个源**——超过 5 个就开始有噪音
- **3 个主流源 + 2 个垂直源**——主流保证广度，垂直保证深度
- **每 3 个月审一次**——源的有效性会变化

## 3. 团队设计（15 min）

### 3.1 4 Agent 团队

| Agent | 职责 | 关键能力 | 失败模式 |
|---|---|---|---|
| **采集 Agent** | 5 个 RSS 源 | RSS / API / 爬虫 | 源失效 |
| **过滤 Agent** | 关键词 + 重复检测 | 关键词匹配 + 相似度 | 误过滤 |
| **摘要 Agent** | 每条 200 字 + 3 判断 | LLM 摘要 | AI 腔 / 失真 |
| **推送 Agent** | 早 9 点推飞书 | 定时任务 + 连接器 | 推送失败 |

### 3.2 任务流

```
RSS 源
  ↓
采集 Agent（5 个源并行）
  ↓
原始素材库
  ↓
过滤 Agent（去重 + 关键词）
  ↓
候选素材（10-20 条）
  ↓
摘要 Agent（200 字 + 3 判断）
  ↓
最终推送（5 条）
  ↓
推送 Agent（早 9 点）
  ↓
飞书/钉钉/邮件
```

### 3.3 关键设计

| 设计点 | 做法 |
|---|---|
| **采集频率** | 每 30 min 跑一次（不是每 5 min，避免被封） |
| **过滤阈值** | 关键词命中 ≥ 1 / 相似度 < 0.7 |
| **摘要长度** | 200 字内（强制） |
| **推送时间** | 早 9:00（用户上班时间） |
| **失败处理** | 推送失败自动重试 3 次 + 通知人工 |

## 4. 现场演示（10 min）

### 4.1 演示准备
- 5 个 RSS 源已配
- 4 个 Agent 已部署
- 飞书连接器已授权

### 4.2 演示步骤

1. **手动触发一次推送**——演示完整流程
2. **故意制造失败**——演示失败模式
3. **演示过滤效果**——让学员看到 100 条 → 5 条的过程

### 4.3 演示话术

讲师话术：

> "**注意看 5 条推送的格式**——每条 200 字内 + 3 条关键判断。
> **不是 5 条原文，是 5 条 AI 摘要后的核心信息。**
> 这才是用户真正看得完的。"

## 5. 与知识库联动（10 min）

### 5.1 三层联动

```
推送的资讯
   ↓
自动归入"待读"知识库（INBOX）
   ↓
读完/打标签后自动归类（TOPIC）
   ↓
三个月后能复用的归档（DOING）
```

### 5.2 与三哥 wiki 知识库体系的连接

讲师话术：

> "**本节直接对接三哥 wiki 的 INBOX 体系**——
> - 推送到 INBOX（待读）
> - 看完打标签
> - 标签自动归到对应 TOPIC
> 
> 三哥已经在用这套体系，**学员可以直接复用**。"

### 5.3 标签体系建议

| 标签类型 | 示例 |
|---|---|
| **领域** | AI / 商业 / 个人成长 |
| **重要度** | ★★★ 高 / ★★ 中 / ★ 低 |
| **可执行** | 行动 / 思考 / 存档 |
| **状态** | 未读 / 在读 / 已读 / 已用 |

## 6. 收尾（5 min）

### 课后作业

```
【作业 1：配一套推送】
- 选 5 个 RSS 源
- 跑通"采集 → 过滤 → 摘要 → 推送"全流程
- 配监控告警

【作业 2：跑 7 天】
- 每天早 9 点收推送
- 记录每天真正读完几条
- 7 天后统计"读完率"（应 > 60%）

【作业 3：调优**
- 根据 7 天数据调整源
- 调整摘要长度
- 调整推送时间
```

### 关键认知

- ✅ **少而准**——5 条好资讯 > 50 条噪音
- ✅ **AI 摘要不是全文**——必须有判断和取舍
- ✅ **必须配监控**——推送失败要立刻知道
