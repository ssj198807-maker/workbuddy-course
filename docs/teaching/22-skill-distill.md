## 1. 为什么需要自创 Skill（15 min）

### 1.1 开场互动

讲师问：

> "WorkBuddy 市场上有 1000+ Skill，**你装了几个？用过的有几个？真正帮你解决过问题的有几个？**"

典型回答：装 10+ 个，常用 1-3 个，真正解决 1 个。

讲师话术：

> "**这就是为什么需要自创 Skill**——市场 90% 满足不了你 10% 的特殊需求。"

### 1.2 自创的 3 个动机

| 动机 | 描述 |
|---|---|
| **复用性** | 你做 5 次的事情值得变 Skill |
| **团队化** | 把"你会的东西"教给 AI 团队 |
| **沉淀** | 把"脑子里的判断标准"写下来 |

### 1.3 关键认知

讲师话术：

> "**Skill 不是越多越好**——一个不精的 Skill 跑 10 次，不如一个精的 Skill 跑 3 次。
> **先少后多，先精后广。**"

## 2. Skill 的本质（10 min）

### 2.1 Skill = 4 件事

```
Skill = 提示词 + 工具调用 + 输入输出校验 + 示例
```

| 组件 | 作用 | 缺它的后果 |
|---|---|---|
| **触发条件** | 什么场景下用 | 用户不知道用 |
| **输入规范** | 用户必须给什么 | 输入乱糟糟 |
| **处理逻辑** | 内部怎么跑 | 输出不稳定 |
| **输出规范** | 交付什么 + 验收 | 验收无标准 |

### 2.2 一个好的 Skill 长啥样（举例）

**Skill 名称**：「非暴力沟通对话改写」

**触发条件**：
- 当用户说"帮我改一下这段对话" / "这段话太冲了"
- 适用于微信对话、邮件、客服回复

**输入规范**：
- 必填：原对话内容
- 选填：对话场景（工作/家庭/朋友）
- 选填：希望的语气

**处理逻辑**：
- 识别对话中的"评判/比较/命令"
- 改写为"观察+感受+需要+请求"四要素
- 保持原意不丢失

**输出规范**：
- 改写后的对话
- 标出"原评判 → 改写点"对照
- 不超过 200 字

## 3. 三类 Skill 设计模式（20 min）

### 3.1 模式 1：提示词型

| 项 | 内容 |
|---|---|
| **定义** | 仅靠 LLM 就能完成 |
| **示例** | 「降低 AI 腔」「标题优化」「错别字检查」 |
| **优点** | 简单、快 |
| **缺点** | 输出不稳定 |

**关键设计点**：
- ✅ 必给 3-5 个示例（含正反例）
- ✅ 必给禁用词清单
- ❌ 不要写超长提示词（> 1000 字就崩）

### 3.2 模式 2：工具型

| 项 | 内容 |
|---|---|
| **定义** | 需要调外部工具 |
| **示例** | 「网页抓取」「PDF 转换」「Excel 公式生成」 |
| **优点** | 稳定、可控 |
| **缺点** | 工具失败 = 全部失败 |

**关键设计点**：
- ✅ 必须有"工具失败"的兜底
- ✅ 必须有"输入校验"
- ✅ 工具调用必须有日志

### 3.3 模式 3：混合型

| 项 | 内容 |
|---|---|
| **定义** | 提示词 + 工具 |
| **示例** | 「公众号排版」（内容生成 + 图片生成） |
| **优点** | 既灵活又可控 |
| **缺点** | 设计复杂 |

**关键设计点**：
- ✅ 提示词和工具的"边界"要清晰
- ✅ 哪个环节用 LLM、哪个环节用工具，要明文写
- ✅ 必须能"分步调试"

### 3.4 选型决策表

| 你的需求 | 推荐模式 |
|---|---|
| 仅改写/优化文本 | 提示词型 |
| 抓数据/调外部系统 | 工具型 |
| 既要生成内容又要调工具 | 混合型 |
| 输出要求严苛（合规/法律） | 工具型 |
| 输出要求灵活（创意/营销） | 提示词型 |

## 4. 蒸馏方法论（15 min）★ 本节重点

### 4.1 5 步蒸馏法

**本章是个人知识蒸馏方法论的工程化**：

```
1. 拆骨架   → 2. 抽原则   → 3. 写示例   → 4. 写校验   → 5. 写提示词
```

### 4.2 每步详解

#### 步骤 1：拆骨架

**做什么**：把书/视频的目录/章节拆出来
**示例**（《非暴力沟通》）：
- 第 1 章：让爱融入生活
- 第 2 章：是什么蒙蔽了爱
- 第 3 章：观察
- 第 4 章：感受与需要
- ...

#### 步骤 2：抽原则

**做什么**：每个章节的核心原则是什么
**示例**：
- 第 3 章原则："区分观察与评论"
- 第 4 章原则："感受的根源是需要"
- 第 5 章原则："提出具体的请求"

#### 步骤 3：写示例

**做什么**：给 LLM 3-5 个示例（含正反例）
**示例**：

```
原对话：「你怎么每次都迟到？」（反例：评论）
改写：「你今天迟到了 15 分钟，我有点担心。」（正例：观察+感受）

原对话：「你应该更努力。」（反例：评判+命令）
改写：「我希望我们能一起找到让你工作更顺的方法。你愿意聊聊吗？」（正例：观察+感受+请求）
```

#### 步骤 4：写校验

**做什么**：输出必须满足什么
**示例**：
- 必须包含"观察+感受+需要+请求"四要素
- 不能有"评判/比较/命令"字眼
- 长度不超过 200 字

#### 步骤 5：写提示词

**做什么**：把所有上面这些串成 Skill
**示例**：

```markdown
# Skill: 非暴力沟通对话改写

## 触发
当用户输入对话文本希望改写

## 输入
- 原对话（必填）
- 场景（选填：工作/家庭/朋友）
- 语气（选填）

## 步骤
1. 识别对话中的评判/比较/命令
2. 改写为观察+感受+需要+请求
3. 保持原意

## 输出
- 改写后的对话
- 对照表（原句 → 改写点）
- 长度 ≤ 200 字

## 校验
- 必须四要素
- 不能有评判/比较/命令
- 长度 ≤ 200 字

## 示例
[上面步骤 3 的示例]
```

## 5. 现场演示（15 min）

### 5.1 演示准备
- 1 本学员熟悉的书
- WorkBuddy Skill 编辑器
- 5 步模板

### 5.2 演示步骤

1. **选章节**——挑 1 个章节
2. **拆骨架 + 抽原则**——现场做
3. **写示例**——给 3 个正反例
4. **写校验**——3 条规则
5. **写提示词**——合成完整 Skill
6. **跑 1 个测试**——验证效果

### 5.3 演示失败模式
- ❌ 示例不够 → 输出不稳定
- ❌ 校验太严 → 没有输出
- ❌ 提示词冗长 → 跑得慢
- ❌ 没正反例 → 容易走偏

---

## 6. 方法论沉淀：P0/P1/P2 分级（10 min）

### 6.1 蒸馏结果的分级体系

讲师话术：

> "**Skill 蒸馏出来后怎么分级？**——
> 推荐使用 P0/P1/P2 三级：
> - **P0**：必须有（核心 Skill）
> - **P1**：应该有（提效 Skill）
> - **P2**：可以有（边缘 Skill）
> 
> 学员可以直接复用这个分级。"

## 7. 收尾（5 min）

### 课后作业

```
【作业 1：蒸馏 1 个 Skill】
基于你熟悉的 1 本书 or 1 个视频
按 5 步法蒸馏成 1 个 Skill

【作业 2：跑 3 个真实场景】
- 至少 3 个不同输入
- 每个都要看是否满足 4 要素（触发/输入/逻辑/输出）

【作业 3：迭代 2 版】
- 第 1 版跑完后看踩坑
- 调整示例/校验/提示词
- 出第 2 版

【作业 4：写"Skill 说明书"】
- 什么场景用
- 不适用场景
- 已知问题
```

### 关键认知

- ✅ **Skill 4 要素**——触发/输入/逻辑/输出
- ✅ **三类模式**——提示词/工具/混合
- ✅ **5 步蒸馏**——拆骨架/抽原则/写示例/写校验/写提示词
- ✅ **先少后多，先精后广**
